# Thin Film Analysis

공정조건·위치별 두께·OM 이미지를 Sample ID로 연결해 시편을 선별하고 공정조건별 결과를 비교하는 브라우저 분석 도구입니다. AI 코딩 도구를 개발과 검증 보조에 활용했으며, 실제 분석은 통계와 영상 처리 규칙으로 실행합니다.

**웹앱:** https://ss3031313-max.github.io/hfo2-lab/

## 실행과 설치

- 웹앱 주소를 Chrome 또는 Edge에서 열고 **앱 설치**를 선택하면 별도 창으로 사용할 수 있습니다.
- **오프라인 실행 준비됨**을 확인한 뒤 인터넷 연결을 끊고 다시 실행해 보세요. 첫 접속과 앱 파일 준비에는 인터넷이 필요합니다.
- 저장소를 ZIP으로 내려받아 압축을 풀고 **`om_demo.html`**을 열면 설치 없이 오프라인으로 실행할 수 있습니다. 실행에 Node.js나 Python은 필요하지 않습니다.
- 새 버전이 있으면 앱의 **새 버전 적용** 버튼으로 갱신합니다. 중요한 자료는 먼저 전체 백업으로 보관하세요.

## 사용 순서

1. **Registration:** Sample Registration 화면의 **OM Images**와 **Measurements**에 사진과 측정 Excel을 각각 첨부하고 Sample ID별 연결을 확인합니다. 사진 순서로 자동 짝을 맞추지 않습니다.
2. **Thickness:** 평균 두께와 CV로 판정합니다. OM 결과는 이 단계의 두께 판정을 바꾸지 않습니다.
3. **OM Analysis:** 사진 등록 후 기준 영역을 자동으로 선택하고 면적률·개수·밀도를 계산합니다. 기준 초과나 자동 기준 영역이 불안정한 이미지를 검토합니다. 왼쪽 초록 드래그는 기준 영역, 오른쪽 보라 드래그는 제외할 검출 영역 선택입니다. 드래그는 선택 단계이며, 제외 사유와 제외 버튼을 적용해야 수치가 갱신됩니다.
4. **Screening · Comparison:** 맨 위의 경향 그래프에서 코팅 횟수에 따른 두께 CV·평균 두께·OM 면적률·검출 밀도를 비교합니다. RPM·농도별 두께 그래프도 선택할 수 있습니다. 기본 그래프는 코팅 횟수별 CV입니다. 다른 공정조건이 같은 비교군에서는 조건별 평균을 선으로 연결하고 값을 직접 표시합니다. 조건이 함께 달라진 자료는 점으로만 표시합니다. 그래프 색은 선택한 두께 지표의 기준이며, 종합 판정은 평균과 CV를 함께 적용합니다.
5. **Recipe 우선순위:** 공정조건이 모두 입력된 그룹부터 충족률 내림차순, 미충족률 오름차순으로 정렬합니다. 동률이면 판정 완료 시편 수가 많고 CV·코팅 횟수가 작은 조건을 우선합니다. 미평가 시편은 미충족으로 세지 않으며, 비율의 분모는 전체 시편 수입니다. 카드·표·CSV의 순서가 같습니다.

## v0.5.7 화면과 비교 탐색

- 주요 화면 이름은 **Thin Film Analysis**, **Sample Registration**, **OM Images**, **Measurements**로 표시합니다. 상단 이동 단계는 **Registration → Thickness → OM Analysis → Screening → Comparison**입니다.
- 전체 글자 크기는 기존 화면 크기를 유지하며 그래프 선을 더 분명하게 표시합니다. 그래프 계산과 판정 기준은 그대로 유지합니다.
- **Comparison**의 **기준 충족 / 검토 대기 / 기준 초과** 카드를 누르면 샘플별 비교표의 첫 해당 시편으로 이동하고 같은 판정의 행들을 강조합니다. 전체 샘플과 기존 정렬은 유지하며 다른 행을 숨기지 않습니다. 해당 시편이 없는 카드는 비활성화됩니다.
- 두께 CV 근거 안내를 펼치면 아래 공식 자료의 요약과 원문 링크를 확인할 수 있습니다. 현재 기본 **CV ≤ 10%**는 그대로이며, 참고 자료의 수치를 자동으로 적용하지 않습니다.

| 참고 자료 | 해석 범위 |
| --- | --- |
| [Laurell Technologies · Tech Notes](https://www.laurell.com/support/tech-notes.php) | 균일도 허용치를 일률적으로 제시하지 않으며 재료·도포 방식·환경에 맞춘 공정 개발이 필요하다고 설명합니다. |
| [FOM Technologies · PEDOT:PSS film uniformity](https://www.fomtechnologies.com/science-and-learning/insights-blog/film-uniformity-in-pedot-pss-coatings/) | PEDOT:PSS 코팅에서 상대 표준편차 5% 미만을 보고한 사례입니다. 재료와 코팅 방식이 달라 HfO₂ 합격 규격으로 직접 적용할 수 없습니다. |

원문 링크 확인에는 인터넷 연결이 필요합니다. 이 자료들은 현재 HfO₂ 시편의 품질 검증을 대신하지 않습니다.

## 입력 파일

| 파일 | 내용 |
| --- | --- |
| `sample_data/HfO2_input_01.xlsx` | 평균 15 nm·CV 약 1.05%인 한 시편 |
| `sample_data/HfO2_input_02.xlsx` | 평균 15 nm·CV 약 21.08%인 한 시편 |
| `sample_data/HfO2_sample_inputs.xlsx` | 두께 충족·초과·미입력 등 여섯 사례 |
| `sample_data/sample_process.csv`, `sample_thickness.csv` | 상세 CSV 입력용 공정조건·두께 파일 |

동봉 입력의 `data_source`는 **SYNTHETIC**이며 실제 측정 결과가 아닙니다. OM 원본 사진은 포함하지 않습니다. 통합 Excel과 같은 Sample ID의 단일 Excel을 중복 첨부하지 마세요. Excel에는 공정조건과 위치별 두께만 입력하며 평균·CV·판정은 앱이 계산합니다. 자세한 열 형식과 사진 연결 방법은 [입력 안내](sample_data/IMPORT_GUIDE.txt)를 참고하세요.

## 계산과 해석

- **두께 CV = 표본 표준편차 ÷ 평균 두께 × 100.** 서로 다른 유효 위치가 두 개 이상일 때 계산합니다. 예시의 다섯 위치는 입력 사례이며 장비의 기본 측정 위치를 뜻하지 않습니다.
- 기본 두께 기준은 평균 **13–17 nm**, **CV ≤ 10%**입니다. 설정에서 변경할 수 있는 초기 선별 기준이며 검증된 HfO₂ 품질 규격은 아닙니다.
- OM은 기준 RGB와의 거리, 8방향 연결 성분, 크기별 면적 필터를 사용합니다. 실제 파티클의 종류나 박막 두께를 자동 확정하지 않습니다.
- OM의 얼룩 의심 면적과 검출 영역 밀도를 각각 판정합니다. 안정된 자동 기준 영역으로 분석한 결과가 두 상한 이내이면 **OM 자동 기준 충족**입니다. 기준 초과·분석 실패·사용자 추가 검토 지정은 별도 표시합니다. 수동 수정 결과는 표시 확인 후 확정하며, 자동 판정과 사용자 확인 기록을 구분해 보관합니다.
- 검출 영역 밀도는 계수 대상 개수 ÷ 분석 영역 픽셀 수 × 10,000입니다. 계수에서 제외하면 개수와 밀도가 함께 감소합니다. 이미 계수에서 제외한 영역을 면적에서도 제외하면 밀도는 그대로이고 면적률만 바뀔 수 있습니다.
- 사진 간 비교에는 배율·해상도·조명과 분석 설정의 일관성이 필요합니다. 결과만으로 젖음성 저하의 원인이나 최적 Recipe를 입증할 수는 없습니다.
- 학습된 AI 모델의 추론, 외부 AI API 호출, 자동 Recipe 생성 기능은 포함하지 않습니다.

## 저장과 백업

등록한 샘플·OM·설정·검토 결과는 현재 PC와 브라우저의 **IndexedDB**에 자동 저장합니다. 입력 자료를 서버로 전송하거나 다른 PC와 자동 동기화하지 않습니다. 화면의 **저장됨** 표시를 확인하세요. 등록 전 선택만 한 파일은 보관되지 않을 수 있습니다.

**02 Thickness**에서 선택한 샘플 또는 전체 샘플의 두께 데이터만 삭제할 수 있습니다. 공정조건과 OM 연결은 유지하며, 판정 결과와 자동저장에도 즉시 반영합니다. 삭제 직후에는 복구할 수 있지만, 새로고침하거나 다른 두께·샘플 변경을 진행하기 전 필요한 백업을 보관하세요.

로컬 HTML에서 웹앱으로 옮길 때는 **전체 백업 → 백업 불러오기**를 사용합니다. 브라우저 데이터 삭제나 프로필 변경에 대비해 JSON 백업과 원본 Excel·사진을 따로 보관하세요. 앱 파일의 오프라인 캐시와 분석 자료의 저장은 별개입니다.

## 소스와 검사

| 경로 | 용도 |
| --- | --- |
| `src/` | 분석·입력·저장·PWA 소스 |
| `build_demo.mjs` | 오프라인 HTML, 웹앱 HTML, 서비스 워커 생성 |
| `review_tests/` | 계산·입력·영역 수정·저장·PWA 검사 |
| `index.html`, `manifest.webmanifest`, `sw.js`, `icons/` | 웹앱 게시 파일 |
| `om_demo.html` | 단일 파일 오프라인 실행본 |

개발·검사에는 Node.js가 필요하며 별도 npm 패키지는 필요하지 않습니다.

```sh
node build_demo.mjs
node --test review_tests/*.test.mjs
```

아이콘을 새로 생성할 때만 Python과 Pillow가 필요합니다. 포함된 PNG 아이콘을 사용한 앱 빌드에는 필요하지 않습니다. 번들 라이브러리의 출처와 라이선스는 [src/vendor/README.txt](src/vendor/README.txt)에 있습니다.

GitHub Pages는 `main` 브랜치의 `/(root)`를 게시 원본으로 사용합니다. 저장소에는 `.nojekyll`이 포함됩니다. 원본 측정자료·사진·개인 백업은 공개 저장소에 넣지 않고 실행 중 파일로 첨부합니다.

### 시편 삭제와 두께값 삭제

두께 분석의 **시편 관리 → 전체 시편 삭제**는 등록 목록·공정조건·두께·분석 및 비교 결과에서 시편을 함께 제거합니다. 두께값이 이미 없는 판정 대기 시편도 삭제할 수 있습니다. OM 사진과 사진별 검토 결과는 유지됩니다. **시편 삭제 복구**는 새로고침하거나 시편 데이터를 변경하기 전까지 사용할 수 있습니다. **두께값만 삭제**는 시편 등록을 유지하므로 두께 자료가 없는 시편은 판정 대기로 표시됩니다.

첫 화면의 **Measurements** 칸에는 공정조건·두께 시트가 있는 Excel(.xlsx) 파일을 첨부합니다.

앱을 새로 열거나 새로고침하면 항상 **01 Registration**에서 시작합니다. 저장된 시편·OM 사진·판정 기준·검토 결과는 그대로 복원됩니다.
